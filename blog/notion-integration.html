Integration

Send spoken tasks from Blurts to a Notion database

Connect Blurts to Notion, choose a task database, understand supported properties, and troubleshoot delivery without assuming two-way synchronization.

By the Blurts team November 9, 2026 3 min read

Capture on your phone and keep the task in Notion

When Notion is where you review work, a voice note left elsewhere creates a second inbox. Blurts can turn a recording into tasks and send them to a selected Notion database. The useful result is a task page in the workspace you already use, with structured details where the destination supports them.

Blurts saves the captured tasks first, then handles Notion delivery as a separate step. A saved task and a successfully delivered Notion page are therefore different outcomes. If the connection needs attention, you can still inspect the captured task in Blurts instead of assuming the whole recording has disappeared.

Connect and choose the destination

Open Blurts settings, choose Notion, and complete the authorization flow. Grant access to the pages or databases you intend to use. A database that your Notion account can see is not necessarily available to the integration until the appropriate access is granted.

When a destination has not been selected, Blurts can offer candidate task databases, let you identify a database by name, or create a new task database under an accessible page. If a selected destination lacks the expected properties, the flow can ask whether to add them. Read that prompt before changing an established workspace database.

  • Start with a database where you are comfortable testing new tasks.
  • Confirm the selected database in the Notion section of settings.
  • Use Reset Database when you need to choose the destination again.

Understand the property mapping

Blurts sends a task title and can map Type, Priority, Area or Category, Due Date, Status, and Description to compatible properties. Mapping depends on recognized property names and types. The current behavior is not an arbitrary schema mapper: a property with the same purpose but an incompatible type may not receive the value you expect.

For example, a newly created Blurts task database uses select fields for type, area, priority, and status, a date field for due date, and a text field for description. An existing Notion project database may use different conventions. Inspect a small test task before relying on a filtered view that requires additional relations, owners, or custom fields.

A useful first test

Record a simple action such as “Check the draft with Sam tomorrow.” Once Blurts shows the saved task, open the selected Notion database and inspect the new page. Check its title, due date, status, and any mapped details. Then check the exact view where you normally review tasks; a page can exist in the database while being hidden by that view’s filters.

After confirming creation, try a harmless title correction from Blurts and inspect the linked page. Blurts also attempts to propagate completion and deletion handling for linked Notion tasks. Deletion archives the Notion page. These operations depend on a valid connection, so treat destination inspection as part of setup rather than proof supplied by a connected badge alone.

Troubleshoot the handoff

If no database appears, check that you authorized the correct workspace and shared an accessible page or database. If a property is missing, inspect its name and type before adding duplicate fields. If the task is saved locally but delivery fails, address the Notion connection or database selection rather than immediately repeating the recording.

The integration is a Blurts-to-Notion workflow. This guide does not promise that changes made directly in Notion flow back automatically, nor that every custom database property is supported. The current free-tier flow allows one integration, while multiple integrations require an eligible paid tier; check the current in-app entitlement before adding another destination.

Common questions

Can I use an existing Notion database?

Yes, when it is accessible and its properties are compatible. Inspect the field mapping with a small test task.

Why is a task missing from my usual Notion view?

Check the underlying database and the view’s filters. A newly created task may lack a custom relation, owner, or other property required by your view.

Does a connected badge prove tasks were delivered?

No. It indicates connection state. Verify the actual task page and handle any delivery error separately.

Try one real thought.

Start with something you actually need to do. Review the result and decide whether the workflow fits your day.
